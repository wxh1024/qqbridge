# QQ聊天桥

Minecraft Java 版 **Fabric 1.21.11 客户端模组**——把游戏内聊天与「玩家进入视野」提醒同步到 **QQ 官方机器人** 所在的群聊，把群内 @官方机器人 的消息转发为游戏内聊天消息，并支持在群里用 `/l <文字>` 遥控角色去按告示牌下方的活板门/按钮（拉珍珠）。

> ⚠️ 本模组是**单可信客户端**桥接方案：QQ 机器人的 `AppSecret` 存在本机配置里，请只在服主 / 房管自己的机器上运行，**不要分发给普通玩家**。

## 功能

| # | 方向 | 说明 |
|---|---|---|
| 1 | 游戏 → QQ | 监听游戏内聊天框消息（玩家聊天 + 系统消息，各有开关），格式化后发到绑定的 QQ 群 |
| 2 | QQ → 游戏 | 群内 **@官方机器人** 发消息后，内容转发为游戏内聊天消息（两种落地模式，见下） |
| 3 | 视野提醒 | 玩家进入视野距离（客户端追踪范围）时，把进入者名称推送到 QQ；同一玩家带冷却防刷屏 |
| 4 | 拉珍珠（QQ 遥控交互） | 群内 **@机器人 `/l <文字>`** → 扫描周围告示牌 → 男中音（Baritone）自动寻路 → 转头 → 点该告示牌下方 2 格内的活板门/按钮，结果回推 QQ（详见下文「拉珍珠」） |

**QQ → 游戏 的两种模式**（配置项 `qqToGameMode`）：

- `send`（默认）：作为你本人的聊天消息发给服务器，**全服可见**（注意：这条消息被服务器回显后会经聊天同步钩子再发回 QQ 一次，属该模式固有效果；不想看到重复回显就用 `local`）；
- `local`：仅在桥接端本机聊天框显示。

**出站消息用 Markdown 格式**（配置项 `markdownToQq`，默认 `true`）：游戏→QQ 的聊天/系统/视野提醒消息走 QQ 官方自定义 Markdown（`msg_type=2`），以引用块样式呈现，玩家名可加粗、格式串里可写 Markdown 语法；`{name}`/`{message}` 插入值自动转义，防止游戏内文字意外触发 Markdown 解析。关掉开关即退回纯文本。

## QQ 平台注意事项

- **主动推送需要群主授权**：QQ 官方机器人 2025-04 曾下线主动消息，2025-06 回归的版本要求群主在手机 QQ 的「机器人设置页」手动打开**推送开关**（群内默认关闭）。不开的话，需求 1/3 的主动推送会被拒。
- **被动回复兜底**：主动推送失败的消息会进本地队列，等下一条 @机器人 消息（5 分钟窗口、每条最多 5 次回复）自动补发到群里。
- **群隔离**：出站只发 `groupOpenid` 指定的那一个群；1.3.2 起兜底队列的冲刷也只认该群的 `msg_id`——机器人同时在多个群时，未绑定群的 @消息 既不会把消息带出去，也不会把队列掏空。
- 平台频控参考：约 20 条/分钟/群、1000 条/天/群；本模组出站默认限速 ≥1.2 秒/条，远低于上限。
- 收到群消息事件的前提：机器人具备群聊能力，且有人 **@机器人**（默认消息范围即「仅@消息」）。

## 获取构建产物

每个 push 都会跑 GitHub Actions（`构建` 工作流），产物保留 120 天：

**仓库 → Actions → 最新「构建」运行 → Artifacts → `QQ聊天桥`**（含 `QQ聊天桥-<版本>.jar`）

> 下载 Artifact 需要登录 GitHub 账号。

### 本地构建

需要 **JDK 25** 运行 Gradle（Loom 1.18+ 的要求；mod 产物本身仍是 Java 21，玩家用 Java 21 即可运行）：

```bash
./gradlew build
# 产物在 build/libs/QQ聊天桥-<版本>.jar
```

## 安装

1. 客户端安装 **Fabric Loader 0.19.5+** 与 **Fabric API**（1.21.11 对应版本）；
2. 把 `QQ聊天桥-<版本>.jar` 放进客户端 `mods/`；
3. 启动一次游戏，生成 `config/qq_bridge.json`，填入机器人凭证后重启。

## 配置（config/qq_bridge.json）

| 字段 | 默认 | 说明 |
|---|---|---|
| `appId` / `clientSecret` | 空 | QQ 开放平台机器人的 AppID / AppSecret（⚠️ 只放可信机器） |
| `sandbox` | `false` | `true` = 沙箱环境（只收沙箱配置的群事件） |
| `groupOpenid` | 空 | 绑定群；**留空则收到首条 @机器人 消息时自动绑定** |
| `syncChatToQq` | `true` | 玩家聊天 → QQ |
| `syncGameMessagesToQq` | `true` | 系统消息 → QQ |
| `forwardQqToGame` | `true` | QQ → 游戏 |
| `notifyPlayerEnter` | `true` | 视野进入提醒 |
| `qqToGameMode` | `"send"` | `send` 全服可见 / `local` 仅本机 |
| `playerEnterCooldownSeconds` | `60` | 同一玩家重复提醒冷却 |
| `sendIntervalMs` | `1200` | 出站最小间隔 |
| `maxPendingMessages` | `50` | 被动兜底队列上限 |
| `markdownToQq` | `true` | 出站到 QQ 用 Markdown 格式（`msg_type=2`，自定义 Markdown，群聊/单聊已开放）；`false` = 退回纯文本 |
| `chatToQqFormat` 等 | 见文件 | 出站到 QQ 的文案格式，`{name}` / `{message}` 占位；`markdownToQq=true` 时可写 Markdown 语法（`**加粗**`、`## 标题`），插入值自动转义。⚠️ 若格式串本身以 `>` 开头，会再被外层引用块包裹（双重 `>>`），建议格式串不要自带 `>` 前缀 |
| `qqToGameFormat` | `"{name}: {message}"` | **入站**到游戏内聊天框的文案，**只支持纯文本**——游戏聊天框不解析 Markdown，写 `**` 只会原样显示成星号 |
| `pearlCommandEnabled` | `true` | 拉珍珠指令总开关 |
| `pearlCommandPrefix` | `"/l"` | 指令前缀：群消息以它开头即触发，**前缀后面全部文字**（`/l珍珠A` 或 `/l 珍珠A`）作为要匹配的文本 |
| `pearlScanRadiusH` / `pearlScanRadiusV` | `16` / `8` | 告示牌搜索半径：水平 ±16 格、垂直 ±8 格 |
| `pearlTriggerDropDepth` | `2` | 触发块相对告示牌向下搜索的格数（1..8） |
| `pearlGoalRadius` | `2` | 男中音 `GoalNear` 落点半径（走到距触发块 ≤2 格算到达） |
| `pearlInteractRange` | `4.0` | 到达后距触发块的最大交互距离（与玩家方块交互距离取较小值） |
| `pearlTaskTimeoutSeconds` | `120` | 单次拉珍珠总超时，超时停寻路并提示 |
| `pearlFeedbackToQq` | `true` | 拉珍珠结果回推 QQ |
| `pearlToQqFormat` | `"**拉珍珠** {message}"` | 回推文案格式，`{message}` 为具体提示 |

改完配置需重启游戏生效。

> 1.3.1 起 `pearlForwardCommand` 已移除（拉珍珠指令**固定不转发**到游戏聊天），老配置里残留该字段会被忽略；
> 老配置的 `qqToGameFormat` 若带 `**` 标记，首次加载时会自动去掉星号并写回。

## 拉珍珠（QQ 遥控交互）

群里发 **@机器人 `/l <文字>`**（`/l` 后面直接跟文字也认，例如 `/l珍珠A`）。模组会在角色身上跑一套状态机：**扫描 → 选目标 → 男中音寻路 → 转头 → 右键 → 回推结果**。

### 搜索范围

- 中心：**收到指令那一刻**角色所在的方块（中途走动不影响本次判定）。
- 立方体范围：水平 ±`pearlScanRadiusH`（默认 16 格）、垂直 ±`pearlScanRadiusV`（默认 8 格）。
- 只遍历客户端**已加载区块**里的方块实体，未加载的告示牌看不到（也就匹配不到）。

### 匹配规则

- 只看告示牌方块实体：**正面 4 行 + 背面 4 行**，任意一行命中即可。
- 该行文本先去掉 `§` 颜色/格式码、再 `trim`，然后与指令后的文字**完全相等**才算命中（区分大小写，不做包含/模糊/正则匹配）。
- 指令后文字为空时不会扫描，直接提示「请在指令后面写上告示牌上那一行的文字」。

### 触发块与交互优先级

1. **多块告示牌都命中**：取距角色**最近**的一块（按方块坐标的欧氏距离）；距离相同则 **y 小 > x 小 > z 小**，保证同一场景结果可复现。
2. **同一块告示牌下的触发块**：从 `y-1` 往下找 `pearlTriggerDropDepth` 格（默认 2，即 `y-1`、`y-2`），**取最先遇到的那一格** → 也就是「离告示牌最近的优先」。
3. 同一格里活板门/按钮不会共存，所以实际优先级就是 **最近的下方格 > 更下面一格**；两类方块地位相同（活板门、按钮都点）。
4. 命中后寻路目标是触发块的 `GoalNear(pearlGoalRadius)`；进入交互距离后先**停止寻路**，再把 yaw/pitch 对准方块并**立即发出 `LookAndOnGround` 视线封包**，稳 3 tick 才发右键——服务端按「最后一次上报的视线」处理方块交互，不转头容易点空或被拒。

> 需要客户端安装 **男中音（Baritone）**；未安装时指令会直接提示「未检测到男中音（Baritone）模组」。本模组只编译期依赖 `baritone.api`，不打包 Baritone。

### 失败/进度提示

所有提示都会同时进**游戏内聊天框**（`[拉珍珠] …`，不会被回推 QQ）和**绑定的 QQ 群**（`pearlFeedbackToQq`）。逐条如下：

| 场景 | 提示（QQ/游戏内一致） |
|---|---|
| 上一个任务没结束 | `上一个拉珍珠任务还在进行，先等等` |
| 指令没带文字 | `请在指令后面写上告示牌上那一行的文字，例如 /l 珍珠A` |
| 没进世界 | `当前没进世界，指令已忽略` |
| 没装男中音 | `未检测到男中音（Baritone）模组，无法自动寻路` |
| 开始扫描 | `开始扫描「文字」（水平 16 格、垂直 ±8 格）` |
| 一块告示牌都没找到 | `范围内（水平 16 格、垂直 ±8 格）没找到任何告示牌` |
| 有告示牌但文字全不匹配 | `范围内 N 块告示牌，没有一行的文字与「文字」完全一致` |
| 文字匹配但下方没机关 | `有 N 块告示牌写着「文字」，但它们下方 2 格内没有活板门或按钮` |
| 命中并开始寻路 | `命中告示牌 (x, y, z)（距 N.N 格），其下方是XX活板门 (x, y, z)，开始自动寻路` |
| 男中音没启动 | `男中音没走起来，已重新下发一次寻路请求`（自动重试一次） |
| 走不到 | `寻路失败：到不了 (x, y, z) 旁（可能被封住/超出范围/无路可走）` |
| 超时 | `任务超时（120 秒），已停止寻路` |
| 交互成功 | `已触发 (x, y, z) 的XX活板门（告示牌「文字」）` |
| 交互被拒 | `已到 (x, y, z) 旁，但交互被拒绝（可能方块已消失、被遮挡或没有权限）` |
| 换世界/退服 | `世界已卸载，任务中止` |

## 使用流程

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，拿到 AppID / AppSecret，开通群聊能力；
2. 把机器人拉进目标 QQ 群，**让群主在机器人设置页打开「推送开关」**（主动消息必需）；
3. 填好 `config/qq_bridge.json` 后进游戏；
4. 在群里 **@机器人** 随便说一句——模组会自动绑定该群并把消息转发进游戏；
5. 之后游戏内聊天、有人进入视野，都会自动同步到该群；
6. 想遥控角色去按机关：群里 **@机器人 `/l <告示牌文字>`**（客户端需装 Baritone）。

联调排查：看游戏日志（`logs/latest.log`）里 `QQ聊天桥` / `qqbridge` 关键字；401 = 凭证错，推送被拒 = 群主没开推送开关，收不到事件 = 机器人没 @ 消息权限或没拉进群。

## 技术栈

- Fabric 1.21.11 · Java 21（产物）· Loom `fabric-loom-remap` + Yarn 映射（`1.21.11+build.6`）
- 零第三方运行时依赖：QQ 协议走 JDK 内置 `java.net.http`（HTTP + WebSocket），JSON 用游戏自带 Gson
- 事件全部走 Fabric API（无 Mixin）：`ClientReceiveMessageEvents` / `ClientTickEvents` / `ClientLifecycleEvents`
- 男中音（Baritone）只在**编译期**用 `baritone.api`（`modCompileOnly libs/baritone-1.21.11-2026.jar`），产物里不含它；运行时缺该模组时拉珍珠会提示未安装
